I opened the Network panel in Chrome Developer Tools and reloaded example.com. I selected the example.com request and checked the Headers section. The request returned a status code of 200 OK, which shows that the HTTP request was successfully processed by the server.

I inspected the HTTP request and response headers using the browser’s Network panel. The request headers contained information such as the Host, User-Agent, and Accept fields. The response headers included information such as Content-Type, Server, and Date. This helped me understand that HTTP headers carry additional information between the client and server. HTTP communication is stateless because each request is handled independently.

I opened the Application panel in Chrome Developer Tools and checked the Cookies section under Storage. This helped me understand where browser cookies are stored and how cookies can be used to maintain information between HTTP requests. Cookies provide a way to manage state even though HTTP itself is stateless.

I accessed https://example.com and inspected the request in the browser’s Network panel. The Request URL showed that HTTPS was being used. HTTPS provides secure communication by using TLS, which helps protect data exchanged between the client and server. This exercise helped me understand the difference between normal HTTP and secure HTTPS communication.

4. Request–Response Understanding

The Internet uses a request-response model for communication between a client and a server. A client sends a request to a server, and the server processes the request and sends back a response. During this laboratory, I observed this process using cURL and the browser Network panel. For example, a GET request was sent to example.com, and the server returned an HTTP 200 OK response. I also tested a non-existing resource and observed a 404 Not Found response. These activities helped me understand how clients and servers communicate using HTTP.
